# 快速开始：环境、构建、运行

> 只想把项目跑起来看这一篇。协议与设计见 [`协议速览.md`](协议速览.md) 和
> [`配件投屏核心原理.md`](配件投屏核心原理.md)；跑不通先看 [`排错手册.md`](排错手册.md)。
> 项目整体介绍见 [README](../README.md)。

## 一、环境要求

| 项 | 要求 | 备注 |
| --- | --- | --- |
| JDK | **17+** | 建议把 `org.gradle.java.home` 写在 **`$GRADLE_USER_HOME/gradle.properties`（用户级）**，别写进项目 —— 绝对路径一旦入库，别的机器 clone 下来会直接构建失败 |
| Android SDK | `compileSdk=36` / `buildTools=36.0.0` | 宿主 `minSdk=23`、配件端 `minSdk=24`；`targetSdk=36` |
| Gradle | 8.14.5（wrapper 已配） | 走腾讯云镜像，无需手动装 |
| `local.properties` | **必须**有 `sdk.dir=<你的 SDK 路径>` | ⚠️ 有些环境 `ANDROID_HOME` 为空，不能靠环境变量 |
| `GRADLE_USER_HOME` | 建议显式设成固定目录 | 依赖缓存按此目录复用；不设则用 `~/.gradle` |

## 二、构建与验证

```bash
# 协议层单测（唯一可以纯本地验证的部分，当前 382 项）
./gradlew :protocol:test

# 两个 APK（宿主一个、配件一个；iPad 不需要装任何东西）
./gradlew :app-host:assembleDebug :app-accessory:assembleDebug
./gradlew :app-host:assembleRelease :app-accessory:assembleRelease

# lint（宿主 minSdk=23，iOS 代码是后并进来的，NewApi 靠它兜）
./gradlew :app-host:lintDebug
```

产物位置：

```
app-host/build/outputs/apk/debug/app-host-debug.apk
app-accessory/build/outputs/apk/debug/app-accessory-debug.apk
```

> **`-release.apk` 不能用来排错**：release 构建下回放入口、抓流落盘、adb 调试 extra、
> 周期统计日志全部被关掉（`DebugTools` 门控）。详见 [`排错手册.md`](排错手册.md) 第 0 节。
> 另外 release 产物默认不签名，直接 `adb install` 会失败。

> 历史上 iOS 是一条独立分支（`:app-ios-qt`，单独 APK）。2026-10-18 合并进 `:app-host` 后
> 该模块已删除 —— 需要单独跑纯 iOS 版本时从 git 历史恢复，合并记录见
> [`合入host_双协议方案.md`](合入host_双协议方案.md)。

### release 签名

release 产物默认**不签名**（`*-release-unsigned.apk`，`adb install` 会直接失败）。
本机已配好一套**私有**密钥，但它**不在仓库里**：

| 东西 | 位置 | 入库 |
| --- | --- | --- |
| keystore | `~/.android/usbscreen-release.jks` | ❌ |
| 口令 / 别名 | `$GRADLE_USER_HOME/gradle.properties` 的 `usbscreen.release.*` | ❌ |
| 构建脚本 | 各模块 `build.gradle.kts`（只读属性，不含秘密） | ✅ |

属性缺失时 **release 保持未签名**，所以别人 clone 下来、以及 CI，都不会因此构建失败。

换机器 / 新克隆：

```bash
# 1) 拷 keystore（⚠️ 重新生成一个也行，但签名就变了，老用户的包无法覆盖升级）
cp <备份>/usbscreen-release.jks ~/.android/

# 2) 把 4 行属性加进 $GRADLE_USER_HOME/gradle.properties（绝对路径）
usbscreen.release.storeFile=C:/Users/<你>/.android/usbscreen-release.jks
usbscreen.release.storePassword=<口令>
usbscreen.release.keyAlias=usbscreen
usbscreen.release.keyPassword=<口令>
```

查本机口令：`grep usbscreen.release $GRADLE_USER_HOME/gradle.properties`

**GitHub Actions**：在仓库 `Settings → Secrets and variables → Actions` 配 4 个 secret：

| Secret | 值 |
| --- | --- |
| `KEYSTORE_BASE64` | `base64 -w0 ~/.android/usbscreen-release.jks` 的输出 |
| `KEYSTORE_PASSWORD` | keystore 口令 |
| `KEY_ALIAS` | `usbscreen` |
| `KEY_PASSWORD` | key 口令（与上面相同） |

CI 会把它解码成 `$RUNNER_TEMP/release.jks`，再把其余三项写进 `~/.gradle/gradle.properties`
—— 与本地读的是**同一组属性**。没配 `KEYSTORE_BASE64` 时这整段跳过，release 仍产出 unsigned。

> debug 包与 release 包**签名不同，不能互相覆盖安装**；换包前先卸载旧的。
> 同一种包之间可以正常升级。

## 三、安装与运行

```bash
# 1) 两个包分别装上（adb 唯一被用到的场景就是这一步）
adb -s <宿主设备>  install -r -g app-host/build/outputs/apk/debug/app-host-debug.apk
adb -s <配件设备>  install -r -g app-accessory/build/outputs/apk/debug/app-accessory-debug.apk

# 2) 打开宿主（也可以直接在桌面上点图标）
adb -s <宿主设备> shell am start -n com.uav.host/.ChooserActivity
```

宿主打开后是**选择页**：两张卡片「安卓手机」/「iPad / iPhone」。插线时能分类就直接进对应页面，
分不清才停在选择页让你点。（卡片名沿用「安卓手机」，实际接手机、平板、车机等任何能跑 AOA
的安卓设备都走这条；判断依据是 VID/PID，与设备类型无关。）

### 安卓设备（AOA）

1. 安卓设备插上宿主 → 系统**可能**弹「**是否打开该 App 处理 USB 配件**」→ 勾选默认（此后插线即达）
2. 设备上弹「**开始录制或投放**」录屏授权 → 允许（Android 14+ 每次都要点）
3. 宿主的 `SurfaceView` 上出现设备画面

### iPad / iPhone（QuickTime USB）

1. iPad 插上宿主 → 自动进入「iPad / iPhone」页，**自动开始**
2. **首次**：iPad 上弹「信任此电脑」→ 点信任（此后永久记住，不用再点）
3. 画面 + 声音自动出来，**不用按任何按钮**

**拔线即停**：拔掉 iPad，界面 1 秒内回到空闲态并提示「iPad 已断开」；再插回去会自动重新开始。

⚠️ **会话一开始，iPad 上的播放会暂停**（设备把音频路由切到 USB 造成的，不是 bug）——
在 iPad 上再点一次播放即可，之后声音由宿主扬声器输出。

## 四、宿主界面

面板是**左侧竖栏**（深色，宽 300dp）。横屏宿主下手机竖屏镜像只占中间一条、两侧是信箱边，
**侧栏正好落在左边黑边里，不挡画面**。

| 控件 | 用途 |
| --- | --- |
| 左上「状态药丸」 | 彩色圆点 + 状态词（空闲 / 连接中 / 投屏中 / 重协商 / 出错）。面板收起后仍可见，**点它就是打开面板** |
| 「扫描 / 重试」 | 手动重新扫描设备。**部分宿主的 USB host 栈在设备重枚举后不发 attach 广播**，此时靠它（App 内已有轮询兜底） |
| 「强制重握手」 | 强制走完整 AOA 握手，重写配件身份。用于「设备被别的宿主 App 切成配件模式」 |
| 「回放抓流」 | 调试用：回放 `.uav` 抓流文件，跳过整个 USB 与握手（**仅 debug 包**） |
| 「画质」分段控件 | `1:1 像素` ↔ `高清`。默认 `1:1`，选择本地持久化 |
| 「链路状态」卡片 | 编码尺寸 / 画质口径 / 帧 / 丢帧 / 队列 / 延迟 / 音频电平（紧凑 4 行） |
| 「重新唤醒采集通道」 | **仅 iPad 页**，唯一保留的手动兜底：设备侧采集通道没被武装、一个字节都不来时点它 |

面板在首帧到达时**自动收起**，点**信箱边空白处**或**状态药丸**可再打开。
界面细节见 [`实施计划.md`](实施计划.md) 10.14 / 10.19 / 10.24。

## 五、adb 命令速查

```bash
# 日志（厂商 ROM 噪音大，按 PID 抓最稳）
adb logcat -s UAV-IosQt:I Chooser:I          # iOS 页 / 选择页
adb logcat --pid=$(adb shell pidof com.uav.host)

# iPad：录制现网码流 → 宿主 files/feed.bin（默认关闭，约 2 MB/s）
adb shell am start -n com.uav.host/.ios.IosActivity --ez record true

# iPad：不插设备，离线回放 feed.bin 验证「解析 → 解码 → 上屏」
adb shell am start -n com.uav.host/.ios.IosActivity --ez replay true

# AOA：调试入口（仅 debug 包，详见 app-host/aoa/debug/DebugIntents.kt）
adb shell am start -n com.uav.host/.aoa.HostActivity --ez scan true
adb shell am start -n com.uav.host/.aoa.HostActivity --ez force_handshake true
adb shell am start -n com.uav.host/.aoa.HostActivity --es replay_path /sdcard/xxx.uav
```

⚠️ **Activity 已在前台时 `am start` 走 `onNewIntent`，不会重新读 extra** —— 要生效先
`am force-stop com.uav.host`。但**别随手 force-stop 配件端**（见下节）。

## 六、环境不稳定点与常见误区

- ⚠️ **「等待重枚举超时」不是 OTG 不稳**（旧结论，已推翻）：真因是我们自己漏掉配件 fd，
  破坏了 `/dev/usb_accessory` 的**独占打开**，于是设备再也切不进配件模式。
  「重插拔即恢复」只是顺带杀掉了持 fd 的进程。**已在 10.8 修掉**（含 3 项回归单测）。
  别再靠拔插去「确认」问题，用 [`实施计划.md`](实施计划.md) 10.8 的 fd 计数法。
- ⚠️ **宿主 kernel panic 是「我们的 App 触发的」，已在 10.16 修掉**。
  旧结论「宿主固件/内核问题，App 层解决不了」是错的：`Comm:` 是 `uav-reader`
  （宿主端**我们的** bulk 读线程），栈是 `usercopy_abort ← __check_object_size ← do_proc_bulk`——
  协议层读 24B 报文头时把**小于端点包长 512B** 的长度透传给了内核，MTK 主机栈不把
  `actual_length` 截到请求长度 ⇒ 越界写 bounce buffer ⇒ 内核崩。
  修法见 10.16（`BufferedByteChannel`：对内核永远整块读 + 残留续读）。**长跑复验仍待做**。
  定性「panic 是谁干的」的正确姿势：读完整 ramoops，搜 `kernel BUG` / `usercopy`，
  **看 `Comm:` 是谁** —— 见 [`排错手册.md`](排错手册.md) 3.9。
- **供电与 OTG 常互斥**：手机当宿主时一边给配件供电、一边自己掉电。
  长时使用建议用 **OTG + 充电二合一线（带 PD 口）**。
- **别随手 `am force-stop` 配件端 App**：App 会进入 stopped 状态，系统此后不再用隐式 intent
  （配件 attach）拉起它，很容易把「链路不通」误判成软件 bug。
- ⚠️ **先后顺序要紧凑：先起配件端、几秒内起宿主端**。配件端有 **12s 空闲看门狗**
  （判定为「假配件」时只释放不重连），间隔拖太久会让配件端先把配件 fd 释放掉，
  宿主随即无限等 CNXN —— 很容易误判成链路 bug。
- **Git Bash 下操作 adb 要设 `export MSYS_NO_PATHCONV=1`**：否则 Android 绝对路径会被改写成
  Windows 路径（`adb push /data/local/tmp/x` 报成功但文件不在那里）。
