# 协议速览（两套链路的约定对照）

> 一页看清两条链路在**线上**长什么样。完整清单与推导见
> [`实施计划.md`](实施计划.md) 第 4 节（AOA）与
> [`iOS_USB投屏_安卓实现.md`](iOS_USB投屏_安卓实现.md)（QuickTime）。

两套协议**没有任何共享字段**，各自独立演进；共用只是 `:protocol` 这个模块容器。

---

## 一、安卓设备：AOA 上的私有流协议

两端必须逐字一致，完整清单见 [`实施计划.md`](实施计划.md) 第 4 节。

| 项 | 约定 |
| --- | --- |
| 报文头 | **24 字节，全小端**：`command / arg0 / arg1 / data_length / data_check / magic` |
| `magic` | `command xor 0xFFFFFFFF` —— **字节流错位的第一道防线**（一旦错位，magic 必然对不上） |
| `data_check` | payload 逐字节无符号累加 |
| 命令字 | `CNXN / OPEN / OKAY / CLSE / WRTE`（裁剪掉 `AUTH` / `STLS`） |
| 流 id | `0=control` / `1=video` / `2=audio`；`WRTE.arg0` 是**唯一的流标识** |
| 流头 | 该流**首条** `WRTE` 的 12 字节 payload：`codecId`(4 ASCII) + `width` + `height` |
| 帧 | 每条 `WRTE` payload = `8B ptsAndFlags` + `4B size` + 码流 |
| `ptsAndFlags` | bit63 = CONFIG、bit62 = KEY_FRAME、bit61 预留方向（本期未启用） |
| 上限 | `data_length` 与帧 `size` 均 ≤ **8 MiB** |
| 超时 | `controlTransfer` **1000ms（严禁 0，0 = 无限等待）**；bulk 读 200ms / 写 5000ms |

另外两个关键约定：

- **CONFIG 帧永不吞掉**：解码器配置依赖它，丢了会导致空参数 `configure`。
- **丢弃 P 帧的代价是花屏**，最长 = I 帧间隔（本项目取 **3s**）。

---

## 二、iPad：QuickTime USB 协议

宿主当 USB 主机，claim 平板的 `0xFF/0x2A` 接口（`0x86` IN / `0x05` OUT）。

| 项 | 约定 |
| --- | --- |
| 报文 | `u32 长度`（含 4B 头）+ 4B fourcc + 负载；**fourcc 线上是字节反转的**（`fcc()` 必用，禁止字面量） |
| 会话 | `PING` → `CWPA`（音频时钟）→ `CVRP`（视频时钟）→ `FEED`/`EAT` |
| 主机→设备 | 全部是 `RPLY`：`clock` / `afmt` / `skew` / `zero`，另有 `NEED`（要下一帧，带视频时钟） |
| 视频 | `ASYN/FEED`：`CmSampleBuf`，`sdat` 段装 H.264 NAL |
| 音频 | `ASYN/EAT!`：同构 sbuf，`sdat` 段装**裸 PCM**（`fdsc` 里给 ASBD，实机 `lpcm 48k/16bit/2ch`） |
| 收尾 | `hpa0`/`hpd0` → 等 2 个 `ASYN/rels`（途中应答 `SYNC stop`）→ 再补 `hpd0` |
| 启用采集 | `activate`（`0x40/0x52 wIndex=2`）只有在**当前配置为 3** 时才真重枚举；判据是「配置集 4→5」 |

⚠️ 这套协议的坑集中在**字节级**：`lpcm` 写成裸 ASCII、`og! ` 与 `go! ` 搞反，都会让设备
**静默不推音频**（不报错、不崩溃）。所以出站报文一律与真机样本做逐字节断言
（`:protocol` 的 `QtPacketFixtureTest`），排查顺序见
[`iOS_USB投屏_安卓实现.md`](iOS_USB投屏_安卓实现.md) §三·五。
