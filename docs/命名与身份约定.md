# 命名与身份约定

> **改名字之前先看这一篇。** 产品名可以随便改，但「包名」和「配件身份」是协议内容，
> 改一处要同步另一处，漏了就是「插线识别不到」或「握手直接失败」。

| 名称 | 值 | 能否随意变更 |
| --- | --- | --- |
| 产品名 | **UsbScreenMirror** | ✅ 随意 |
| Gradle 工程名 | `usbscreen` | ✅ 随意（仅影响 IDE 显示） |
| Android 包名 | `com.uav.host` / `com.uav.accessory` | ⚠️ 改了等于换应用，两端必须同步 |
| 配件身份 | `UAV` / `usbscreen` / `1.0` | ⚠️ **这是协议内容**，见下 |

## 配件身份三处必须逐字一致

（`manufacturer` / `model` / `version`）**参与系统匹配**，三处必须完全相同：

1. `:protocol` 的 `AccessoryIdentity`（实际握手时发出的字符串，`SEND_STRING` 是
   **UTF-8 + 单个 `\0`**）；
2. `app-accessory` 的 `res/xml/accessory_filter.xml`（**手工镜像**，XML 引用不了 Kotlin 常量）；
3. 以及任何引用这两个值的文档/脚本。

⚠️ 因为 XML 无法引用 Kotlin 常量，这属于**手工镜像**：改一处必须同步另一处。
漏改的典型症状是「配件 App 装好了，但插线时系统不派发 `USB_ACCESSORY_ATTACHED`」——
看起来像链路问题，其实是身份不匹配。

## 组件全名（adb 与文档里都会用到）

| 组件 | 全名 |
| --- | --- |
| 选择页（唯一 LAUNCHER） | `com.uav.host/.ChooserActivity` |
| AOA 投屏页 | `com.uav.host/.aoa.HostActivity` |
| QuickTime 投屏页 | `com.uav.host/.ios.IosActivity` |
| 配件端录屏授权页 | `com.uav.accessory/.ProjectionActivity` |
| 配件端采集服务 | `com.uav.accessory/.CaptureService` |

> `app-host` 里 `ChooserActivity` 留在根包，两个投屏页分别收在 `aoa/` 与 `ios/` 下
> —— 与「一条链路一个包」的结构对应。清单里声明的组件名是**字符串**，重构搬包时
> 编译不会报错，必须手工同步（见 [`项目状态与路线图.md`](项目状态与路线图.md) 10.24 的教训）。
